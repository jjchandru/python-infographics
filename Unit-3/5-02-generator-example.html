UNIT 3.5 - ITERATORS

(2)

A function that remembers where it left off, using yield

EXAMPLE

def count_up():
    print("returning 1")
    yield 1
    print("returning 2")
    yield 2
    print("returning 3")
    yield 3

gen = count_up()
print(gen)
print("Generator created")

print(next(gen))
print(next(gen))
print(next(gen))
print(next(gen))

Output:
<generator object count_up at 0x001A2B3C4D5E6>
Generator created
returning 1
1
returning 2
2
returning 3
3
StopIteration

EXPLANATION

  • Calling count_up() doesn't run any of the function's code yet — notice neither "returning 1" nor anything else from inside the function appears before "Generator created". It just hands back a generator object, gen, without starting execution.
  • print(gen) shows <generator object count_up at ...> — the memory address changes every run and isn't important; what matters is the type, "generator object," proving gen is not the value 1, 2, or 3, just something that can produce them later.
  • Each next(gen) resumes the function exactly where it paused last time — that's why "returning 2" only appears on the second call, not the first.
  • yield is like return, except the function pauses instead of ending, keeping all its local state intact until the next next() call.
  • Once the function runs off the end with no more yield left, the fourth next(gen) raises StopIteration — same exhaustion behaviour as the iterator on the previous page.
  • Values are produced one at a time, only when asked for, instead of all being built and stored up front — this is what "lazy evaluation" means.
